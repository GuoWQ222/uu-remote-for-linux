- [ ] 客户端窗口可见且无持续白屏
- [ ] 网易账号登录成功
- [ ] 关闭并重新启动后登录状态保持

- [ ] 目标设备已被另一台电脑控制时，本机打开连接会稳定显示“接管设备”确认框

## 4. 输入

- [ ] 鼠标移动、左右键、滚轮正常

- [ ] 诊断显示“Wine 本地输入法：已禁用（远端输入法接管）”

- [ ] 反复按 Win+Space 只切换远端输入法，本机不会出现雾凇候选框

- [ ] Ctrl/Alt/Shift 组合键正常
- [ ] 剪贴板文本复制粘贴正常

## 5. 辅助功能

- [ ] 小文件上传与下载正常

- [ ] 关闭“防止电脑休眠”后 2 秒内释放 Linux 休眠抑制
- [ ] 执行 `--stop` 后 2 秒内释放 Linux 休眠抑制
- [ ] `--enable-wol` 只选择默认路由对应的有线物理网卡
- [ ] WOL 诊断显示 Magic Packet 已配置且识别补丁完整
- [ ] 重启 UU 后日志中的 `networkcard_wol` 从 `0` 变为 `1`
- [ ] UU 设置页可继续进入路由器/辅助设备配置，不再误报网卡不支持
- [ ] `uuremote:` URI 可打开
- [ ] `--stop` 只停止本项目前缀
- [ ] `--repair` 后账号和设备数据仍保留

## 明确不在本轮验收范围

- 登录管理器，以及尚未保存 Portal 授权的 Wayland 无人值守被控；
- 隐私屏、虚拟显示器；
- HDR、4K/144Hz；
- 游戏手柄和多点触控。

# Linux X11 被控端输入（0.9.2+）

1. 确认登录会话为 X11，启动 UU 后运行
   `uu-remote-for-linux --diagnose`。
2. 确认 `Win64 输入钩子` 为“完整”，`被控端原生输入` 为“生效中”，
   并显示“钩子 v9”。
3. 从另一台电脑连接本机，确认远端鼠标可见且可移动。
4. 持续移动鼠标并运行诊断，确认 `被控端输入事件` 的“移动”计数增长。

# Linux Wayland 被控端画面与输入（1.1.1+）

1. 确认 `echo "$XDG_SESSION_TYPE"` 输出 `wayland`，并且 `DISPLAY` 与
   `WAYLAND_DISPLAY` 均已设置。
2. 启动 UU；首次运行在“远程桌面”系统窗口中选择显示器，开启“允许远程
   交互”，然后点击“共享”。
3. 运行 `uu-remote-for-linux --diagnose`，确认 `桌面后端` 为
   `wayland-xwayland`，`被控端原生输入` 中包含 `wayland-portal`，并且
   `Wayland 画面桥` 显示“生效中（Portal → Win64 GDI；帧 数字）”。
4. 从另一台设备连接，验证相对/绝对鼠标移动、左右键、滚轮、字母、方向键、
   Super 组合键，并确认输入事件计数增长。
5. 退出并重新启动 UU，确认系统不再重复询问显示器，诊断中的
   `Wayland 授权恢复` 为“已保存”。
6. 分别打开一个原生 Wayland 窗口和一个 XWayland 窗口，确认 Windows
   控制端都能看到画面且不再是黑屏。
7. 依次验收左键、右键、双击、滚轮、拖拽和键盘输入，并确认相应计数
   增长。
8. 按住一个键或鼠标按钮后主动断开连接；最多等待 15 秒，确认本机没有
   遗留按下状态。
9. 运行 `uu-remote-for-linux --stop`，确认输入桥停止并释放所有按键和
   鼠标按钮。
# Linux 登录自启动（0.3.3+）

1. 正常启动 UU，打开设置页并开启“开机自动启动”。
2. 最多等待 2 秒，运行 `uu-remote-for-linux --diagnose`，确认：
   - `UU 自启动开关` 为“开启”；
   - `Linux 自启动项` 为“已创建”；
   - `自启动兼容桥` 为“就绪”。
3. 注销并重新登录 Linux，确认 UU 自动启动且仍使用原 Wine 前缀。
4. 在 UU 设置页关闭开关，再次运行诊断，确认 Linux 自启动项已删除。

# 防止电脑休眠（0.4.0+）

1. 正常启动 UU，在设置页开启“防止电脑休眠”。
2. 最多等待 2 秒，运行 `uu-remote-for-linux --diagnose`，确认：
   - `UU 防休眠开关` 为“开启”；
   - `Linux 休眠抑制` 为“生效中”；
   - `防休眠兼容桥` 为“就绪”。
3. 运行 `systemd-inhibit --list --no-pager`，确认存在
   `uu-remote-for-linux` 的 `sleep:idle`、`block` 条目。
4. 关闭 UU 开关，最多等待 2 秒，确认该 inhibitor 消失。
5. 再次开启开关，然后执行 `uu-remote-for-linux --stop`，确认
   inhibitor 在 2 秒内消失。

# 允许远程开机（0.5.1+）

1. 运行 `sudo ethtool <有线网卡>`，确认 `Supports Wake-on` 包含 `g`。
2. 运行 `uu-remote-for-linux --enable-wol`，完成授权后检查诊断：
   - `Linux WOL 状态` 为“Magic Packet 已配置”；
   - `UU 后台进程托管` 为“Server/Healthd 生效中”；
   - `UU WOL 兼容桥` 为“已启用”；
   - `UU WOL 识别补丁` 为“完整”。
3. 重启 UU，确认服务端日志报告 `networkcard_wol = 1`。
4. 在 UU 设置页继续绑定受支持的路由器或同网段在线辅助设备。
5. 只有诊断显示 `UU 远程开机开关` 为“已开启”后，才能做真实断电测试。
6. 企业/实验室设备先获得 IT 许可；不要为了测试擅自修改 BIOS、自动登录
   或园区网络策略。

# 安全自动更新（0.6.0+）

1. 在 UU 设置页开启“自动更新”，运行 `uu-remote-for-linux --diagnose`，
   确认“UU 自动更新开关”为“开启”、“自动更新兼容桥”为“就绪”、
   “官方更新器保护”为“完整”。
2. 运行 `uu-remote-for-linux --check-update`，当前已经是最新版时确认
   客户端保持运行且诊断显示“已是最新版本”。
3. 检查安装目录中的 `Upgrade.exe` 与软件包内占位程序完全一致，并确认
   `Upgrade.uu-remote-original.exe` 仍存在。
4. 发现未收录的新版本时，确认诊断显示“已暂缓”，当前 UU 版本和
   `d3d11.dll`、`dxgi.dll`、`streamer.dll`、`GameViewerServer.exe`
   哈希均未变化。
5. 对已收录版本执行更新后，确认所有已启用桥的诊断项仍为“完整”；
   若注入故障进行回滚测试，确认诊断显示“更新失败并已回滚”且旧版仍能
   正常连接。
6. 在设置页关闭“自动更新”，确认兼容桥日志记录开关关闭，后续不再自动
   请求官方发布接口；手动 `--check-update` 仍可使用。
